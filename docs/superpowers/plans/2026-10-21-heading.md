# Heading and distance control

Goal: keep the starting heading during encoder-based relative translation and support absolute/relative turns.

Architecture: 5 ms chassis task owns commands and motor output. Encoder position deltas feed world-coordinate odometry; position P control produces body velocity, wrapped heading P control produces angular velocity. Existing velocity ramp and wheel scaling remain.

- [x] Add independently timestamped IMU/encoder/status feedback. Reject autonomous commands without fresh feedback; stop and latch faults on feedback loss, disabled motor, or motion timeout. Explicit stop clears the fault only when feedback is healthy.
- [x] Replace motor position commands with encoder distance control (3 mm tolerance), heading control (1 degree tolerance), and 200 ms settling. Bound translation to 400 mm/s and turning to 90 deg/s. Use shortest-path angles; relative turns limited to +/-180 degrees.
- [x] Transfer UART bytes to task context; retain F/B/L/R millimetres; add signed integer A absolute degrees, T relative degrees, S stop. Reject malformed commands. Commands during active motion return busy; do not silently overwrite motion.
- [x] Replace busy-wait scheduling with absolute RTOS tick deadlines; retain DWT for measured control dt.
- [x] Build Debug and run host behavioral tests covering heading wrap, distance convergence, stale feedback and command parsing. Hardware tuning remains necessary for wheel direction, IMU sign, geometry, tolerances and gains.

No flashing is included. Existing uncommitted changes are retained as the starting point.
