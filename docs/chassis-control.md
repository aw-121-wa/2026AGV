# 底盘控制与串口指令

USART6 使用原有串口参数。每条命令建议以 `\r\n` 结束；也兼容一次发送一条、不带换行的命令（以 UART IDLE 结束）。不要把无换行命令分多次发送。多条命令用换行或空格分隔。

| 命令 | 动作 |
| --- | --- |
| `F1000` / `B1000` | 沿启动时车头方向前进 / 后退 1000 mm，保持启动航向 |
| `L500` / `R500` | 沿启动时车体方向左移 / 右移 500 mm，保持启动航向 |
| `A90` | 转到 IMU 坐标系的绝对航向 90°，走最短角路径 |
| `A0` | 转到 IMU 坐标系的 0°；不是自动记录的上电航向 |
| `T90` / `T-90` | 相对当前位置逆时针 / 顺时针转 90° |
| `S` | 停车；反馈正常后也用于解除故障锁定 |

角度输入为整数，范围 -180～180°；相对 +/-180° 保留指定转向方向。距离向量最大 5000 mm。运动中新的运动命令返回 BUSY，不排队；完成后再发下一条。`chassis_cmd_status` 可在调试器查看最近命令的 HAL_OK/HAL_BUSY/HAL_ERROR，本版本不增加串口应答协议。

底盘任务统一执行所有运动 API，中断仅缓存串口数据。`Chassis_MoveRequest` 保留单槽中断接口，但不提供结果反馈；任务代码优先调用 `Chassis_MoveDistance`、`Chassis_TurnTo`、`Chassis_TurnBy`。

定距采用轮编码器位置增量计算世界坐标里程，位置 P 环输出车体系 vx/vy；IMU 航向 P 环输出 wz，然后经过速度斜坡、麦轮解算和轮速限幅。四轮反馈轮询一圈为 80 ms。底盘任务采用 5 ms RTOS 绝对周期调度，DWT 用于测量实际 dt，不再忙等。状态、位置、转速或 IMU 反馈超过 500 ms、驱动故障、掉使能或运动超过 30 s，会停车并锁定故障，不自动恢复运动。

可调参数集中在 `APP/Chassis_motor/chassis.h`：默认平移上限 400 mm/s、转向上限 90 deg/s、位置 Kp=1.5、航向 Kp=2.0。位置误差不超过 3 mm、角度误差不超过 1°、各轮反馈速度不超过 2 RPM，持续 200 ms 后结束运动。这些是软件判定阈值，不代表实车已达到相同精度。

先验证 `T10` 与 `T-10` 的实际方向以及 IMU 读数：逆时针必须为正，必要时调整 `CHASSIS_YAW_SIGN`。编码器方向、轮径、轮距、打滑和轮询延迟都会影响定距精度；当前版本没有外部定位补偿。速度模式 `Chassis_SetVelocity` 仍直接接受 wz，不自动锁航向。

验证：`python tests/run_host.py` 编译实际控制源码运行理想轮组仿真，覆盖航向跨界、+/-180°方向、移动中航向扰动、世界坐标移动、80 ms 编码器轮询、反馈丢失、运动超时、停车重发、无效命令和缓冲区溢出。固件构建：`cmake --preset Debug`，`cmake --build --preset Debug`。尚未烧录或实车调参。

## 陀螺仪 DMA 接收

UART5 使用 DMA1_Stream0 循环接收，启用 IDLE、HT、TC 接收事件。256 字节 DMA 缓冲区由链接脚本放在 RAM_D2（当前地址 `0x30000000`），HWT101 初始化时启用 SRAM1 时钟，并使用 MPU region 1 将该区域配置为不可缓存；该 MPU 区域需保留给驱动。

中断按 DMA 当前写入位置将新增字节转存到 512 字节软件队列，IMU 任务解析帧头和校验。UART5 与 DMA1_Stream0 中断保持相同抢占优先级 6，避免交接过程互相抢占；必须保留 DMA 半满中断。115200、8N1 满速时，半缓冲约 11 ms，避免长时间屏蔽中断导致 DMA 覆盖尚未转存的数据。

每批数据携带接收事件时间戳，防止任务延迟或后续无效数据将旧航向误标为新数据。队列溢出会丢弃碎片并重新同步；UART/DMA 错误由任务清理并重启接收。接收事件统一在 `APP/uart_callbacks.c` 分发，USART6 命令接口保持不变。`.ioc` 同步改为循环 DMA；重新生成 CubeMX 工程后仍需保留链接脚本中的 `.imu_dma` 段。

主机 DMA 测试覆盖跨帧、跨缓冲区、持续流、重复事件、回调分发、校验错误、软件队列溢出、接收重启与时间戳。DMA 总线及中断时序仍需上板验证。
