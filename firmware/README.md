# 2026AGV

STM32H750 + FreeRTOS 麦克纳姆轮 AGV 固件。

- 底盘：4 台 ZDT_X42S 二代闭环步进（X 固件协议），经 FDCAN2 以 1 Mbps 驱动，轮速同步缓存 + 广播触发。
- 姿态：HWT101 陀螺仪，UART5 + DMA 循环接收，帧校验后得到航向角。
- 导航：2400 × 2400 mm 栅格地图（构型空间位图）+ 分步 A* + 中国邮路（奇度点匹配 + Hierholzer）生成覆盖 12 条通道的巡检回路；整圈用一条连续路径执行，不在每个航点停车。
- 交互：USART6 一条串口同时做命令输入和文本状态输出，串口助手就能用；调参和看曲线可以用带界面的调试台 `tools/agv_console.html`（4.5 节）。
- 机械臂：并联 SCARA（平面五连杆），两台 ZDT_X42S 各带一根大臂，和底盘在同一条 CAN 上（地址 5、6）。机械臂模式 `AGV_MODE=3` 底盘一直停着，用调试台标定点位、跟随指定颜色的物料（13 节）。

## 1. 硬件与引脚

MCU 时钟：HSE 8 MHz → PLL1（M=2, N=240, P=2）→ **SYSCLK 480 MHz**，HCLK 240 MHz，APB1/2/3/4 均 120 MHz。
Flash 128 KB，DTCM 128 KB，AXI SRAM（`0x24000000`）512 KB，SRAM1~3（`0x30000000`）288 KB。
上电后可用调试器读 `g_hse_ok`（1 = 外部晶振起振）和 `g_sysclk_hz`（应为 480000000）确认时钟。

### 1.1 串口 / 总线一览

| 外设 | 引脚 | 参数 | 用途 | 中断 / DMA |
|---|---|---|---|---|
| **USART6** | PC6 = TX，PC7 = RX | 115200 8N1，无流控 | **命令 + 文本输出**：串口助手或调试台收发（见第 4 节） | USART6_IRQn 优先级 6；收发都用中断（`ReceiveToIdle_IT` / `Transmit_IT`），不占 DMA |
| **UART5** | PC12 = TX，PD2 = RX | 115200 8N1 | **HWT101 陀螺仪**专用，只收不发（TX 预留） | UART5_IRQn 优先级 6 + DMA1_Stream0 循环模式 + 空闲中断；DMA 缓冲 256 B 固定放 RAM_D2 |
| **FDCAN2** | PB12 = RX，PB13 = TX | 经典 CAN，**1 Mbps**，扩展帧 | 4 台轮子 + 2 台机械臂的 ZDT_X42S；不设硬件滤波器，地址在任务里过滤 | FDCAN2_IT0 优先级 5；RX FIFO0 16 帧、TX FIFO 队列 16 帧 |
| **TIM6** | — | 1 ms 周期 | HAL 时基（`HAL_GetTick()` / `uwTick`） | TIM6_DAC_IRQn 优先级 15 |

> 没有单独的调试串口：`printf` 没有落地（`syscalls.c` 的 `__io_putchar` 是弱符号），调试信息一律走 USART6 文本输出或调试器变量。

### 1.2 电机地址（按实车接线修改 `User/Drivers/ZDT_X42S/zdt_x42s.h`）

| 地址 | 位置 | 说明 |
|---|---|---|
| 1 | LF 左前 | `ZDT_ADDR_LF` |
| 2 | RF 右前 | `ZDT_ADDR_RF` |
| 3 | LR 左后 | `ZDT_ADDR_LR` |
| 4 | RR 右后 | `ZDT_ADDR_RR` |
| 5 | 机械臂 J1 | `ARM_ADDR_J1`（`User/Arm/arm.h`），只有机械臂模式注册 |
| 6 | 机械臂 J2 | `ARM_ADDR_J2` |
| 0 | 广播 | 只用于同步触发 `00 FF 66 6B`，不能做节点地址 |

接线要点：

- 驱动器出厂 CAN 波特率是 500 K，**每台都要在菜单里把 `CAN_Baud` 改成 1M**（手册选项 09），否则收不到任何回复。
- 总线两端各接 120 Ω 终端电阻；四台电机并联在同一对 CANH/CANL 上。
- 轮径 78.16 mm（卡尺 77.0，按“F2400 实走 2436 mm”标定过，里程和速度一起修正）、横移系数 0.968（按“L2400 实走约 2324 mm”标定）、横移带前后 0.0208（按“R2400 往后偏”标定了两轮）、轴距 210 mm、轮距 230.4 mm 都在 `chassis.h` 顶部修改。

## 3. 运行模式与状态机

| AGV_MODE | 含义 |
|---|---|
| 0 COMMAND | 串口指令模式，底盘按 USART6 命令走（`CHASSIS_COMMAND_SPEED_MM_S`，默认 1200 mm/s，比赛模式开车也用它） |
| 1 SURVEY | 纯底盘跑全图巡检。上电不走，等调试台“巡检”面板选出发区、点“开始跑图”（发 `/start 1` 或 `/start 2`）；跑完、停了、故障以后把车放回出发区可以再跑（`AGV_SURVEY_SPEED_MM_S`，默认 1200 mm/s） |
| 2 COMPETITION | 开局流程（`/start`，见 9.6 节）：雷达扫全图、读任务码；取放料流程待接入。流程没跑时底盘可以用串口命令手动开 |
| 3 ARM | 机械臂模式（13 节）：底盘一直停着、轮子锁住，`F/B/L/R/T/A/W` 一律 `BUSY`；`/arm` 命令和调试台“机械臂”页标定点位、点动、跟随物料，`S` 停机械臂 |

底盘模式（`chassis.mode`）：`VEL` 速度模式 / `MOVE` 定距 / `TURN` 转向 / `PATH` 连续航点。

巡检状态机（`AgvState`）：

```
IDLE ──/start <出发区>──> WAIT ──READY──> DOCK_OUT ──> PLAN(需要时) ──> DRIVE ──> DOCK_IN ──> DONE
 ↑                         └──15s 超时──┐        └──碰障/位姿/地图/底盘/超时──> FAULT
 └── DONE / STOPPED / FAULT 以后再发 /start 重新开始（底盘要 READY、停着）
```

`/start` 必须带出发区（1 = 右上 (2250, 2250)，2 = 右下 (2250, 150)），车放在那个出发区中心、车头朝 +X。
跑着再发回 `BUSY`；`S` 停下记成 STOPPED，没在跑时 `S` 不改状态。状态行 `AGV ... zone=<出发区>`。

- `DOCK_OUT`：出发区中心 → 通道口（两段 L 形），并为整圈航点做碰撞预检。
- `DRIVE`：逐段规划（通道内无碰撞直接走直线，否则在走廊内做 A*），把航点**累积**成一条路径。
- `DOCK_IN`：航点全部就绪后一次性 `Chassis_FollowPath()` 执行整圈，随后入库。
- `executing` 期间持续检查：偏线 > `AGV_CROSS_TRACK_MM`（默认 40 mm）、地图版本变化、位姿越界、整圈总超时。
- 完成后 `agv.covered` 是规划覆盖的通道位图，`agv.home_residual_mm` 是里程计回库残差（只上报，不判故障）。

## 4. 串口交互（USART6）

所有输入输出都是可读的 ASCII 文本，任何串口助手（XCOM、SSCOM、MobaXterm、PuTTY、VOFA+ 的串口文本模式等）都能用；要界面就用调试台（4.5 节）。

串口助手设置：**115200、8 数据位、无校验、1 停止位、无流控**；接收区用"文本/ASCII"显示（不要勾 HEX）；发送时勾不勾"加回车换行"都可以（没有换行时靠串口空闲中断判定一条结束）。输出全是英文 ASCII，GBK / UTF-8 都不会乱码。

### 4.1 命令

| 命令 | 含义 | 例子 |
|---|---|---|
| `F<mm>` `B<mm>` `L<mm>` `R<mm>` | 前 / 后 / 左 / 右平移，整数 1~5000 mm | `F300` |
| `T<deg>` | 相对转角，±180°，最多 3 位小数 | `T90`、`T-45.5` |
| `A<deg>` | 转到绝对航向 | `A0` |
| `S` | 立即停车；**也是清故障命令**（自动解除堵转保护、重新使能） | `S` |
| `W` / `W1`~`W4` | 单轮方向测试（全部 / 只测 LF、RF、LR、RR）。**先把车架起来让轮子离地** | `W` |
| `I` | 打印详细诊断：IMU、每个电机的使能/堵转/收帧计数、CAN 计数 | `I` |
| `D<hz>` | 周期状态行频率：`D0` 关闭，`D1`~`D10` Hz（默认 1 Hz） | `D5` |
| `H` 或 `?` | 打印帮助 | `?` |

规则：

- 不分大小写；一行可以写多条，用空格分隔，按顺序执行：`F300 L200 B300 R200`。
- **整行原子**：整行解析通过才提交，有一处错就整行不执行，回 `ERR`。
- 运动中发新的移动命令会**排队追加**到当前路径；`S` 立即生效并丢弃该行剩余内容。
- 指令模式移动速度 100 mm/s（`agv_config.h` 的 `CHASSIS_COMMAND_SPEED_MM_S`）。
- 巡检模式下只接受 `S`、`I`、`D`、`H` 和控制台命令（4.4 节），其余回 `BUSY`。比赛模式流程没跑时移动命令和 `W` 都能用；流程运行中规则禁止遥控，同样只接受这几个，`S` 中止流程。

### 4.2 串口输出

| 开头 | 什么时候出现 | 含义 |
|---|---|---|
| `====` | 上电 | 开机信息：运行模式、是否用陀螺仪 |
| `EVT` | 状态变化 | `IDLE -> READY`、`READY -> FAULT: <原因>` 等，原因会具体到哪个轮子 |
| `[  12.3]` | 周期（默认每秒一行） | 时间(s) 状态 模式 里程计 x/y(mm) 航向/目标/误差(°) 下发速度 vx/vy(mm/s)/wz(°/s)，四轮目标/实测转速(RPM)；IDLE 时后面跟 `waiting: ...` 说明还在等什么 |
| `OK` / `BUSY` / `ERR` | 每次发命令 | 命令回执；`OK` 只表示已接受 |
| `DONE path` | 一条路径走完 | 用时、里程、最大偏线、最大航向误差；这条路径期间控制节拍的最大偏差和单拍最长占用（`jitter`、`loop`，µs） |
| `LOG` / `L` | 发 `/log`，或 `/log on` 以后每个动作做完 | 调参日志：`LOG begin`、两行 `LOG param`、每拍一行 `L`、`LOG end`（11.5 节）。调试台的“自动调参”读它，终端里默认不显示 `L` 行 |
| `RUN` / `ROUTE` / `COMP` | 比赛模式 | 流程状态、路线、雷达和任务码（9.4 节） |
| `WHEEL` / `DONE wheel test` | 单轮测试 | 正在转哪个轮子、编码器检查结果 |
| `---- info` | 发 `I` | 详细诊断 |

示例（上电 → 走一段 → 单轮测试 → 堵转）：

```text
==== 2026AGV chassis firmware | mode=COMMAND | IMU=HWT101 | CAN 1M ====
Type H (or ?) + Enter for help. Status line every 1000 ms (D0 = off).
EVT  IDLE: enabling motors, waiting for feedback
[    1.0] IDLE STOP x=0.0 y=0.0 yaw=0.00 ... | waiting: IMU:no-data LF:no-reply LF:disabled ...
EVT  IDLE -> READY: all 4 motors enabled, feedback OK
OK   path queued (100 mm/s)
[    2.0] READY PATH x=49.5 y=0.0 yaw=0.00 tgt=0.00 err=0.00 v=50/0/0.0 rpm(t/m) LF 12/12 RF 12/12 LR 12/12 RR 12/12
DONE path: time=8.11s dist=493.3mm max_cross=2.44mm max_heading=0.00deg jitter=12us loop=340us
OK   wheel test started, 30 rpm 1000 ms per wheel
WHEEL RF spinning now (addr 2): it must roll FORWARD (top of the wheel moves toward the front). If it rolls backward set CHASSIS_WHEEL_DIR_RF to -1
WHEEL RF encoder: expect +180deg got 179.1deg (30.0 rpm) -> OK
DONE wheel test: encoders all OK. Direction = what you saw: every wheel must have rolled forward.
EVT  READY -> FAULT: feedback lost/motor fault: RF:stall. Send S to clear.
ERR  bad command 'Q' (H for help)
```

### 4.3 现场底盘单测步骤（只接电机，其余硬件没到也能测）

1. **CAN 与电机**：每台驱动器菜单里 `CAN_Baud` 设 1M、地址设 1~4（LF/RF/LR/RR），总线两端 120 Ω。
2. **没装陀螺仪**时编译：`cmake --preset Release -DCHASSIS_USE_IMU=0`（航向用轮子推算，只用于单测）。装了就用默认。
3. 上电看串口：应出现 `EVT IDLE -> READY`。一直停在 IDLE 就看状态行的 `waiting:`：
   - `LF:no-reply` → 这台电机没回帧：查 CAN 线、波特率、地址、电机供电；发 `I` 看 `rx_ok` 是否在涨、`bus_off` 是否在涨。
     `I` 里每个轮子一行 `FB`：位置/转速/状态多久没更新、`got/sent`（收到/发出的读取）、`fail`（没能入队）；`CAN:` 那行的 `errors` 是上电以来的总线错误帧数，`rx_lost` 是接收 FIFO 满了丢的帧。`motor` 行末的 `acked/cmd` 是收到的命令应答/发出去的命令（速度、使能、停止）。正常时 `got` 和 `sent`、`acked` 和 `cmd` 都只差在途的一两条，`errors` 基本不涨。进过故障还会多出 `last fault` 和几行 `SNAP`，是进故障那一刻的同样数据。
     固件每拍要发的帧拍末一起发：按电机地址从大到小分组，同一台的读取和速度命令挨着，广播同步放最后。ZDT 的命令和应答是同一个 CAN ID，发给一台驱动器的帧要是排在它的应答后面，两边会撞成错误帧（原来后轮回复少 2%~4%、7 分钟错误两万多次就是这样）。一台驱动器一拍最多收两帧：收三帧时，它对第一帧的应答正好撞上第三帧。反馈读取在拍末排在这一拍所有命令后面，哪台这一拍已经有两条命令（`S`、故障停车是急停加零速，清故障是解除保护加零速），就不读它，下一轮再读；定距、转向、路径自己走完时轮子已经停稳，只下发零速，不发急停（原来每走完一段右后轮少一条命令应答、错误多二十来次）。正常跑的时候 `errors` 应该不涨；上电那一下驱动器还没起来时会有一些（没有节点应答），所以看 `errors` 要比较上电后和跑完后两次 `I` 的差。
   - `LF:disabled` → 回帧了但没使能（驱动器 En 引脚/菜单设置）。
   - `IMU:no-data` → 陀螺仪没数据；没装就按第 2 步编译。
4. **车架起来，轮子离地**，发 `W`。四个轮子依次各转 1 秒，**眼睛看每个轮子是不是往"车前进"的方向滚**。往后滚的轮子，在 `chassis.h` 把对应 `CHASSIS_WHEEL_DIR_xx` 改成 `-1`（或 CMake `-DCHASSIS_WHEEL_DIR_RF=-1`），重新编译再测，直到四个都往前。编码器检查给 `NO MOTION` 就查使能/接线。（左右电机一般镜像安装，通常右侧两个要改 -1。）
5. 放回地面，低速试：`F200`、`B200`、`L200`、`R200`，看车是不是往对的方向走；再 `T90`、`T-90` 看转向方向（逆时针为正）。转反了改 `CHASSIS_YAW_SIGN`。
6. 组合：`F500 L500 B500 R500` 走一个方框，看 `DONE path` 的 `max_cross`、回到原点的 x/y。
7. 出现 `FAULT` 时串口会写原因，处理后发 `S` 清除（堵转保护会自动解除，电机会重新使能）。

### 4.4 串口控制台：实时改参数、看曲线

行首是 `/` 的一行是控制台命令，其他行还是上面的单字母命令。三种模式都能用，不用重新烧录。

| 命令 | 作用 |
|---|---|
| `/` 或 `/help` | 控制台帮助 |
| `/list [前缀]` | 列出参数：当前值、范围、默认值。例：`/list heading` |
| `/set <名字> <值>` | 检查范围后立即生效，回显旧值和新值。例：`/set heading_kp 2.5` |
| `/reset` | 全部恢复默认值，只能在停车时用 |
| `/plot <heading\|speed\|wheels> [hz]` | 输出绘图数据，1~100 Hz，默认 50；`/plot off` 停止 |
| `/log [on\|off]` | `/log` 发最近一个动作的调参日志（还在动就等做完再发，没有回 `LOG none`）；`/log on` 以后每个动作做完自动发，`/log off` 关（11.5 节） |
| `/mode` | 回复运行模式，调试台靠它认模式 |

比赛模式（`AGV_MODE=2`）另有台架调试命令：

| 命令 | 作用 |
|---|---|
| `/start` | 比赛模式：开局流程（9.6 节）。比赛时要接启动按钮，这个命令是台架调试用的 |
| `/start <1\|2>` | 巡检模式：从出发区 1 或 2 开始跑一趟（2.x 节巡检状态机），出发区必须给 |
| `/run` | 流程现在到哪一步 |
| `/task` | 再打印一次任务码 |
| `/task <任务码>` | 当作扫到了这个码，走同一套校验，合法的码替换现有的。没有扫码模块时也能测后面的流程 |
| `/task clear` | 忘掉任务码，重新打开扫码口 |
| `/vision <模式> [颜色]` | 设置上位机视觉任务：0 关、1 二维码、2 物料、3 圆环；颜色 0 任意，1~6 同规则编号 |
| `/obs` | 列出雷达障碍物和扫描状态 |
| `/scan` | 清掉障碍物（同时重建地图、通知上位机），在车现在的位置扫一次。只能停车时用 |
| `/pose <x> <y> <航向>` | 把车搬到某处后设定场地位姿（mm、度），需要底盘 READY、停着 |
| `/route <x> <y>` | 从当前位姿规划到 (x, y)，车不动。A* 分很多拍做，约 0.6~2 秒，结果用 `ROUTE` 行报告。车头要接近直角 |
| `/route go` | 照规划好的路线走，速度用 `cmd_speed`。规划之后车动过、路被挡了都会拒绝 |
| `/route` | 再打印一次路线状态和路线点 |

比赛流程运行中只能看不能改：`/help`、`/list`、`/mode`、`/plot`、`/log`、`/obs`、`/run`、不带参数的 `/task` 和 `/route` 可以用，其余回 `BUSY`，只有 `S` 能停。

机械臂模式（`AGV_MODE=3`，13 节）的命令，角度是度、位置是车体系 mm：

| 命令 | 作用 |
|---|---|
| `/arm` | 打印机械臂和视觉两行状态（和周期状态行后面那两行一样） |
| `/arm hold`、`/arm free` | 锁住；松开电机用手掰（示教）。松开前先停 |
| `/arm j <q1> <q2> [侧]` | 两根大臂走到这两个角度，同时出发同时到。带侧（0/1：记这组角度时末端在两个肘连线的哪一侧）而末端现在不在那一侧，先过死点再走过去 |
| `/arm xy <x> <y>` | 末端走到这一点：几组逆解里挑走过去不经过死点、离现在最近的。只在末端现在这一侧找，另一侧才够得着会说先 `/arm swing` |
| `/arm swing` | 过死点，换到另一侧（另一个工作区），见 13.2。要先停稳 |
| `/arm side <0\|1>` | 改固件记的那一侧，臂不动：没甩过去、末端落回原来那边时用 |
| `/arm deadpoint` | 死点标定：两根小臂掰成一条直线时发，按现在的关节角算两根小臂的长度（改 `arm_b1/2`，回复和 `/set` 一样） |
| `/arm jog <j1\|j2\|x\|y> <步长>` | 点动：从目标算起，连点几下会累加 |
| `/arm zero [<q1> <q2>]` | 把现在的姿态定为这两个角度（默认 0 0）：改 `arm_zero1/2`，回复和 `/set` 一样，臂不动 |
| `/arm camdir` | 相机装在小臂上时，把那根小臂现在的方向定为相机正向（改 `arm_cam_rot`） |
| `/arm save <名字>` | 记下现在的关节角和末端在哪一侧；名字 1~11 个小写字母、数字、下划线，字母开头，最多 16 个点 |
| `/arm point <名字> <q1> <q2> [侧]` | 直接写一个点位（调试台把电脑上存的点位写回固件用）；不写侧就是现在这一侧 |
| `/arm go <名字>`、`/arm del <名字>`、`/arm points` | 去、删、列出点位（`ARM point <名字> <q1> <q2> <侧>`）。去另一侧的点先过死点 |
| `/arm follow <颜色\|off>` | 跟随这个颜色的物料：`red yellow blue green black lightblue` 或编号 1~6 |

运动命令回 `OK   arm to q=..,..`；`BUSY` 说明没锁住、在对齐或在动；`ERR` 分三种：超限位、够不着（没有合得拢又离死点够远的姿态）、路上经过死点（先去一个中间点）。走完打印 `ARM done`。

| 马上，臂不动 | `arm_flip1`、`arm_flip2` | 0 | 0~1 | 1 = 电机正转时那根大臂顺时针转 |
| 下一次运动 | `arm_q1_min`…`arm_q2_max` | ±170 | ±180 | 两根大臂的限位，度 |
| 下一次运动 | `arm_speed`、`arm_acc` | 180、900 | 5~720、10~5000 | 关节最大角速度 °/s、角加速度 °/s² |
| 马上 | `arm_smooth` | 40 | 0~200 | 发给电机的位置按最近这么多毫秒平均：起步、停下更柔，每次运动晚这么久到；0 = 不平滑 |
| 下一次过死点 | `arm_swing_speed`、`arm_swing_run` | 400、100 | 50~2000、20~200 | 过死点时末端的速度 mm/s（慢了会停在死点上）；从末端离两个肘的连线多远开始助跑、过去以后停在多远 mm |
| 下一帧物料 | `arm_cam` | 1 | 0~2 | 相机：0 固定在车上，1 装在 J1 那根小臂上，2 装在 J2 那根小臂上 |
| 下一帧物料 | `arm_cam_rot` | 0 | ±180 | 装在小臂上：那根小臂朝这个方向时画面上方朝车头；固定：画面再转这么多 |
| 下一帧物料 | `arm_cam_x`、`arm_cam_y` | 0、-200 | ±500 | 相机固定在车上时，画面 `TARGET_PX` 那一点在车体系的位置 |
| 下一帧物料 | `arm_cam_lag` | 60 | 0~300 | 拍照到单片机收到物料帧的延迟，ms |

**怎么用：**

- **值只在 RAM 里，断电就没了。** H750VB 内部 Flash 只有一个 128 KB 扇区，放的就是程序，擦它存参数会把程序一起擦掉。调试台会记下改过的值，上电后提示写回；不用调试台时把 `/set` 命令存成文本贴回去。定稿后把数值写回 `chassis.h`、`agv_config.h`、`comp_config.h` 的宏；机械臂的参数和点位用调试台“导出 arm_calib.h”整个替换 `User/Config/arm_calib.h`。
- **发送方式：** 一次发一整行。串口助手勾不勾“加回车换行”都行，不加时靠串口空闲判定一行结束。PuTTY 这类终端要打开本地行编辑（Terminal → Local line editing = Force on），否则每敲一个字符就算一行。
- **控制台行里的 `s` 不算停车，** 否则 `/set heading_tol ...` 会把车停下。
- **绘图：** 每行是 `plot:a,b,c`，开始时会回复每一列的含义。`heading` 是目标航向、航向、误差、目标角速度、下发角速度；`speed` 是目标、下发、实测的 vx 和 vy；`wheels` 是四轮目标和实测转速（LF RF LR RR）。调参时先发 `D0` 关掉状态行。115200 波特约 11 KB/s，一行约 50 字节，`/plot wheels 100` 也跟得上。这种带标签的逗号分隔文本就是 VOFA+ FireWater 模式的格式（还没用 VOFA+ 实测）。
- **无线调试：** USART6 接一个串口无线模块，车跑起来也能用控制台，固件不用改。规则允许和笔记本通信，但运行中不能遥控，所以比赛流程运行时固件只接受查询和 `S`。

## 6. 底盘与导航实现要点

- **运动学**：轮速 = 符号矩阵 × (vx, vy, K·ω)。`Mᵀ·M = 4I`，所以正解取 `Mᵀ/4`。超限时四轮同乘一个系数，保证合成速度方向不歪。
- **同步下发**：四个轮速带同步标志入队（`ZDT_SYNC_CACHE`），再广播一次 `00 FF 66 6B` 同时生效；命令变化才发，另有 100 ms 兜底重发。
- **里程计**：每 20 ms 同时读四轮位置，四轮都更新后才用位置差分累加位移；采样时刻存在 `s_odom_sample_ms[]`，用于 PATH 模式的 40 ms 内预测。
- **航向**：IMU 帧带接收时间戳，超过 500 ms 没新帧就判反馈失效。
- **连续路径**：拐角用二次贝塞尔在两侧各裁 `min(2×容差, 0.25×段长)`，入弯/出弯按向心加速度限速；推进条件是 `距离 ≤ 0.15 mm` 或 `已越过且距离 < 拐角容差`，因此 2 mm 间距的航点也不会被跳过，滞后的车越过圆弧上的点也不会掉头回去追。圆弧那段的速度上限是 `sqrt(acc_linear × 拐角系数 × 半径)`，系数 `CHASSIS_PATH_CORNER_FACTOR` 现在取 1.0（按满线加速度算），90° 弯半径约 8 mm → 约 126 mm/s。**跑图默认 `AGV_STOP_EACH_SEGMENT=1`，拐角不插圆弧、停稳再走**：直线上穿过路口的航点直接过去不停；拐角停在 `path_deviation` 以内就算到（进过一次就不再追它），等四个轮子实测停了再换方向。**刹车曲线计入轮子的滞后** `path_lag`：`v·lag + v²/(2a) = 剩余距离`。不算它时，1200 mm/s 冲过航点“车速 × 滞后”（50~70 mm）再倒回来追，就是原来连续过弯拐不过去的原因。仿真圈速 22.8 s（连续过弯 23.3 s）；轮子晚 60 ms 的假车上，逐段停车冲过拐点不超过 5 mm、不倒车（`tune_log_test`）。
- **偏线统计**：每个内部点记着自己属于哪个原始航点（`s_path_vertex`），偏线只量控制器正在走的那几段原始折线，含拐角两侧，所以贝塞尔裁掉的部分也算在内。不按位置找最近段：巡检路线会重复经过同一条边，那样会匹配到后面重合的段。参考点满 257 个时丢已走过的点；万一当前段被挤掉，退回量当前弦长并置截断标志。
- **A***：障碍只改构型空间位图（每格 10 mm），搜索窗口只清窗口内的表，每拍 32 节点，控制节拍不会被大块 memset 打断。
- **巡检路线**：12 条通道 = 3×3 网格的 12 条边，奇度点（4 个中点）两两配最短路径补 4 条重复边，得到 16 段欧拉回路，回到出发点。

## 7. 配置与编译期校验

`User/Config/agv_config.h` 里的配置（以及 `chassis.h` 里的 `CHASSIS_USE_IMU`、`CHASSIS_WHEEL_DIR_xx`）都可以在 CMake 配置时用 `-D` 覆盖（`CMakeLists.txt` 会把它们加进 `target_compile_definitions`）：

```bash
cmake --preset Release -DAGV_MODE=2 -DAGV_START_ZONE=2 -DAGV_SURVEY_LAPS=2
```

| 宏 | 默认 | 说明 |
|---|---|---|
| `AGV_MODE` | 0 | 运行模式 0~3（3 节） |
| `AGV_START_ZONE` | 1 | 比赛模式的启停区 1 或 2；巡检模式不用它，出发区开始时用 `/start` 选 |
| `AGV_SURVEY_LAPS` | 1 | 巡检圈数 1~8，只有最后一圈入库 |
| `AGV_STOP_EACH_SEGMENT` | 1 | 1 = 拐角停稳再走（默认，直线上的航点不停，避免换向时轮子带速过零），0 = 连续过弯（贝塞尔圆弧） |
| `AGV_SURVEY_SPEED_MM_S` | 1200 | 巡检速度（原 400 的 3 倍，跟指令模式一样快）；可 `-D` 覆盖，运行时钳位到 10~2000 |
| `CHASSIS_PATH_CORNER_FACTOR` | 1.0 | 拐角圆弧的向心加速度预算，`cap = sqrt(acc_linear × 系数 × 半径)`；0.25 = 原来 63 mm/s，1.0 = 126 mm/s |
| `AGV_POSITION_TOL_MM` | 5 | 回库定位目标值，**只作统计** |
| `AGV_CROSS_TRACK_MM` | 40 | 路径跟踪偏线故障阈值（原 8，按 400 mm/s 整定；1200 mm/s 刹车的几十毫米过冲会误报） |
| `AGV_HEADING_FAULT_DEG` / `_MS` | 3.0 / 200 | 航向持续超限多久判故障 |
| `CHASSIS_USE_IMU` | 1 | 0 = 不接陀螺仪，航向由轮子推算（只用于底盘单测） |
| `CHASSIS_WHEEL_DIR_LF/RF/LR/RR` | 1 | 电机安装方向，±1；用 `W` 测试后修改 |
| `CHASSIS_COMMAND_SPEED_MM_S` | 1200 | 指令模式、比赛模式的移动速度（`cmd_speed` 的默认值） |

文件里的写法是 `#ifndef X → 默认值 → #endif` 加 `#if … #error`：

- `#ifndef` 给**默认值**：命令行传了 `-DAGV_SURVEY_LAPS=2` 就不会重复定义（否则编译告警/报错），没传则用默认。
- `#if … #error` 做**编译期合法性检查**：0 圈、9 圈、逐段停车开关写成 2 这类组合直接编译失败，不会带上车跑。
- `AGV_RAM` 在 ARM 上展开成 `.agv_ram` 段属性，主机测试（x86）展开为空，同一份代码两边都能编。

## 9. 内存与 RTOS

| 区域 | 起点 | 内容 |
|---|---|---|
| FLASH 128 KB | `0x08000000` | 代码与常量。比赛模式 Release 60%、Debug 69%；指令模式 Release 51%、Debug 58%；巡检模式 Release 51%。Debug 用 `-Og`（`-O0` 时比赛模式已到 99.6%） |
| DTCM 128 KB | `0x20000000` | `.data/.bss`、主栈、FreeRTOS 堆（15 KB）、任务栈（比赛模式 72%，其他 65%） |
| AXI SRAM 512 KB | `0x24000000` | `.agv_ram`：A* 四张表（`cost/heap/position` 2 B + `parent` 1 B，合计约 394 KB）+ 地图位图 7.2 KB（约 78%） |
| SRAM1 256 B | `0x30000000` | `.imu_dma`：UART5 的 DMA 缓冲，链接脚本断言必须在 `0x30000000` 且 ≤ 256 B |

> A* 表按 57600 格 × 7 B 计算，占满了 RAM 段的大部分，这也是 RAM 78% 的来源；要省 RAM 就减 `MAP_CELL_MM` 或缩小 `MAP_WIDTH_MM/HEIGHT_MM`。

| 任务 | 优先级 | 栈 | 周期 | 说明 |
|---|---|---|---|---|
| IMUTask | High | 1 KB | 事件驱动 | UART5 中断里 `osThreadFlagsSet` 唤醒，10 ms 超时兜底检查 DMA 重启 |
| ChassisTask | AboveNormal | 2 KB | 5 ms（`osDelayUntil`） | 底盘闭环 → 命令/遥测 → 巡检状态机 → 比赛框架，同一拍，控制计算永远在最前面 |
| Timer/IDLE | 低 | 1 KB / 128 B | — | FreeRTOS 内置 |

`configCHECK_FOR_STACK_OVERFLOW = 2`：溢出时 `vApplicationStackOverflowHook` 先给四轮发停止，再停机，任务名留在 `stack_overflow_task` 供调试器查看。

实测栈占用（`-fstack-usage`，O0）：底盘任务最坏链约 **0.6 KB / 2 KB**（`ChassisTelemetry_Poll → PrintStatus 152 B` + `vsnprintf`，文本缓冲都是静态的），IMU 任务最坏约 0.35 KB / 1 KB（`HAL_UART_AbortReceive` 重启路径）。比赛模式多一条更深的链（Release）：`Comp_Tick 144 B → VisionTick 480 B → AcceptTask → Printf` + `vsnprintf`，约 1.1 KB / 2 KB。

**文本输出不影响控制周期和底盘精度：**

- 每拍先做 `Chassis_Update`（反馈、闭环、下发轮速），输出在它后面，所以输出花的时间不会推迟本拍的控制；只有整拍超过 5 ms，下一拍才会晚。
- 输出只把文本放进 2 KB 环形缓冲，由 USART6 中断发送，从不等串口；缓冲满了丢弃新文本并计数。
- 路线可能有几百行，一拍只发一行，缓冲过半就等，状态行和回执总有地方放。A* 一拍最多扩展 32 个节点、清 512 格。
- 雷达和扫码模块只在需要时处理：开动时雷达的接收中断关着，读到任务码后扫码口关掉。
- **主机测试：** `comp_route_test` 把同一条路线跑两遍，一遍输出全关，一遍状态行 10 Hz、曲线 100 Hz、不断查询，每拍下发的四轮转速和位姿逐位相同。
- **实车怎么确认：** 每条路径的 `DONE path` 行带 `jitter`（控制节拍最大偏差）和 `loop`（单拍最长占用，从控制开始到这一拍做完，含中断和高优先级任务），都是这条路径期间的；`I` 里是开机以来的最大值。`loop` 明显小于 5000 µs 就没有影响。这两个数要上车才有，主机上时钟是假的。
- 例外：`/scan`、`/start` 重建地图要十几毫秒（有障碍物时才重建），只能停车时用，车停着不受影响。

## 10. 调试与已知限制

- 没有单独的调试串口；看状态用 USART6 文本输出（状态行、`I` 命令），或调试器看 `chassis`、`agv`、`chassis_path_result`、`chassis_wheel_result`、`stack_overflow_task`、`g_hse_ok`。
- 电机侧计数：`zdt_motor.rx_frames` / `rx_errors` / `ack_pending`，以及 `ZDT_RxDropped()`、`ZDT_BusOffCount()`（串口 `I` 命令都会打印）。
- 命令接收缓冲 32 B/包、环形队列 256 字符；文本发送缓冲 2 KB，满了丢弃新文本并计数（`I` 里的 `tx_dropped`）。
- 巡检整圈是一条 256 航点上限的路径（`CHASSIS_PATH_CAPACITY`），超出会报 `AGV_ERR_PATH`；8 圈约 132 个航点，仍在范围内。
- `S` 会丢弃本行剩余内容、"接收溢出"会丢弃到下一个结束符，这是有意的：宁可丢一行，也不执行半条路径。
- CAN 必须是 1 Mbps，且电机 `CAN_Baud` 要逐台改；否则轮子完全不动。
- 运动中分批发命令时，两批接缝处的拐角没有贝塞尔过渡，只靠出弯限速，理想模型下偏线约 7 mm，超过 5 mm 的拐角容差。要拐得准就写在同一行：`F300 L200`。
- 车总是停在到位容差的边上：`distance_tol` 默认 1 mm，所以长距离会稳定差 1 mm 左右。原来 3 mm 时实测 `F2400` 多走 3 mm 正好是它；要更准就继续调小（0.5 mm 是下限），代价是到位更慢。
- 雷达在开局流程之后就关了：比赛中途被碰歪、或开局路上一直被挡住的障碍物，车不会知道（见 9.2 节）。
- 边走边扫一轮约 2 s 才写一次地图：走着时才露出来的障碍物，400 mm/s 下车已经走出去约 800 mm，离得太近就来不及停。第一段路有启停区停着扫的那轮保证；规则里障碍物开局前就摆好，只有被别的东西挡着的才会晚看到。
- 伸着的雷达按半径 28 mm 的圆算，舵机支架没算：装好以后支架伸出车身的部分要一起量，`COMP_LIDAR_RADIUS_MM` 改大。
- **两个启停区摆车朝向不一样**：启停区 1 车头朝 +Y，启停区 2 车头朝 +X（9.6 节）。摆错了固件以为的朝向差 90°，整张地图都是歪的。启停区本身还是编译时定的（`AGV_START_ZONE`）或现场用 `/pose` 改，`/start` 不检查。
- 启停区 2 在板前要原地转 90°，转的时候车角扫过半径 191 mm 的圆。板子附近障碍物多、1100~1300 和两头 180 mm 内都转不开时报 `RUN failed route`，车不动：仿真 5 个障碍物时约 1.1% 的布局、8 个时约 2.0%。
- 看不清的判断只看这一段从哪儿出发、往哪边走，不管之前在别处扫描时看没看到过，宁可多报：绕障碍物往右或往车头走的路段都报 blind，随机布局两个启停区 24 组里各有 6、8 组有，都没撞。
- 舵机没有位置反馈，转一次固定等 `COMP_LIDAR_SERVO_MS`（800 ms）：开局多等 0.8 s，启停区 2 板前转身前后各多 0.8 s。实测舵机转得快可以改小。
- 开局流程结束后车停在原地，后面的取料、放料还没有，见 9.6 节。

## 11. 调参速查：PID 与限速

### 11.1 固件里一共就两个闭环

| 环 | 位置 | 对象 | 输出 |
|---|---|---|---|
| **航向 PI** | `chassis.c` 的 `Chassis_HeadingControl()` | `heading_error`（°） | `wz`（deg/s），限幅 `CHASSIS_TURN_MAX_SPEED` |
| **定距 P** | `chassis.c` 的 `Chassis_AutoControl()` | 剩余距离（mm） | `vx/vy`（mm/s） |

- 航向 PI 是**唯一**的 PID 型环，MOVE / TURN / PATH 三种模式共用；PATH 模式只是把 `heading_target` 按航段进度插值。
- PATH 模式的位置**不是 PID**：方向直接指向当前航点，速度由几何前馈 + 刹车曲线算出来（`chassis_path.inc`），没有位置积分。
- **轮速环在 ZDT_X42S 驱动器内部**（闭环步进自己的速度/位置环），固件只下发 0.1 RPM 目标，固件里没有它的 PID；要调在驱动器菜单里调。
- **现在没有动作走定距模式**：串口 F/B/L/R/T/A、巡检、比赛都用路径跟踪（PATH），比赛到板前的转向用原地转（TURN），所以 `distance_kp` 实际上不起作用；路径终点前的减速写死在 `chassis_path.inc`（`8 × 剩余距离`）。

### 11.2 改 PID：现场用 `/set`，定稿写回 `User/Chassis/chassis.h` 顶部这几个宏

下面的宏是开机默认值，运行时用 `/set` 改（4.4 节），不用重新烧录。

| 宏 | 当前值 | 作用 | 调大的效果 |
|---|---|---|---|
| `CHASSIS_HEADING_KP` | 2.0 | 航向比例增益，`(deg/s)/deg` | 回正更快，过大开始左右抖 |
| `CHASSIS_HEADING_KI` | 1.0 | 航向积分增益 | 消稳态误差更快，过大会超调/来回摆 |
| `CHASSIS_HEADING_I_MAX` | 5.0 | 积分输出上限（deg/s） | 允许更大的积分修正 |
| `CHASSIS_HEADING_I_ZONE` | 8.0 | 只在误差小于该值时才积分（°） | 大角度转向时更早开始积分 |
| `CHASSIS_TURN_MAX_SPEED` | 90 | 航向环输出限幅（deg/s） | 转向更快，也更容易过冲 |
| `CHASSIS_HEADING_TOL_DEG` | 0.1 | 静态"到位"门限（°） | 更容易判到位（不是增益，但影响 `AGV_DONE` 时机） |
| `CHASSIS_DYNAMIC_TOL_DEG` | 0.2 | 平移期航向误差统计门限（°），超了 `I` 里的 `over_0.2deg` 加一 | 只影响指标，不影响控制 |
| `CHASSIS_SETTLE_US` | 200000 | 停稳多久算完成（µs） | 完成判据更宽松 |
| `CHASSIS_DISTANCE_KP` | 1.5 | 定距 P 增益，`1/s` | 定距更快，过大会冲过头 |
| `CHASSIS_DISTANCE_TOL_MM` | 1.0 | 定距到位容差（mm） | 更容易到位 |

要改控制结构（加微分、换 PID、改积分抗饱和方式）就动 `Chassis_HeadingControl()` / `Chassis_AutoControl()` 本体。

调参顺序建议：

1. 先确认方向：手推车头偏左、状态行的 `yaw` 应该是**变大**（逆时针为正）。方向反了先改 `CHASSIS_YAW_SIGN`，这不是增益问题。
2. `CHASSIS_HEADING_KI = 0`，只加 `KP` 直到回正开始等幅抖，再退到一半。
3. 加 `KI` 到稳态误差消失，`I_ZONE` 取"正常平移误差的量级"（现在 8°，先不动）。
4. 发 `I` 看 `heading: peak_dynamic` 和 `over_0.2deg`：目标分别是 ≤0.2° 和 0，超了就是增益或加速度不匹配。
5. 改完跑 `python tests/run_tests.py`，`path_test` 会验证过弯不失速、偏线 ≤5 mm；`chassis_test` 验证 0.3° 小转向和 8° 扰动恢复。

### 11.3 改限速：先确定你要改的是哪一层

| 想要的效果 | 改哪里 |
|---|---|
| **指令模式**整体快慢（F/B/L/R 的默认速度） | 现场 `/set cmd_speed 150`；默认值是 `User/Config/agv_config.h` 的 `CHASSIS_COMMAND_SPEED_MM_S`（100 mm/s） |
| **巡检模式**整体快慢 | `User/Config/agv_config.h` 的 `AGV_SURVEY_SPEED_MM_S`（默认 150），也可以 `cmake -DAGV_SURVEY_SPEED_MM_S=200` 直接从命令行覆盖 |
| **绝对上限**（任何模式都过不去） | `chassis.h` 的 `CHASSIS_MAX_WHEEL_RPM`（400 RPM，解算后四轮等比缩放）；`Chassis_SetMoveSpeedLimit` 会把目标速度钳位到 10~400（`chassis.h` 的 `CHASSIS_MOVE_MAX_SPEED`） |
| **过弯速度**（现在 90° 弯 ≈50 mm/s） | 现场 `/set acc_linear`、`/set path_deviation`；默认值是 `chassis.h` 的 `CHASSIS_ACC_LINEAR`、`CHASSIS_PATH_DEVIATION_MM`。90° 弯的限速 = `sqrt(a·0.25·r)`，r 最大就是拐角容差，所以想更快只能加加速度或放宽容差。直线不受影响，靠刹车曲线减到拐角速度 |
| **起步/刹车手感** | 现场 `/set acc_linear`、`/set acc_angular`；默认值是 `chassis.h` 的 `CHASSIS_ACC_LINEAR`（前向和横向共用）、`CHASSIS_ACC_ANGULAR` |
| **转向角速度** | 现场 `/set turn_max_speed`；默认值是 `chassis.h` 的 `CHASSIS_TURN_MAX_SPEED`（90 deg/s） |
| **VEL 手工遥控**（调试用 `Chassis_SetVelocity`） | `chassis.h` 的 `CHASSIS_MAX_LINEAR` / `CHASSIS_MAX_ANGULAR` |

速度在固件里的合成顺序（改任何一个都要知道它被谁盖住）：

```
s_move_speed_limit（指令 100 / 巡检 150，Chassis_SetMoveSpeedLimit 设置，仅 VEL 模式生效）
  → 直线航点限速 s_path_limit = s_move_speed_limit
  → 拐角航点限速 s_path_limit = min(s_move_speed_limit, sqrt(a·0.25·r))
  → 出弯限速 exit_speed = min(s_move_speed_limit, sqrt(a·dev·c/(1-c)))
  → 刹车曲线 speed = min(s_move_speed_limit, sqrt(exit² + 2·a·剩余距离))
  → 逆解后整体限幅 CHASSIS_MAX_WHEEL_RPM
```

注意：`Chassis_SetMoveSpeedLimit()` 只在 `mode == VEL` 时接受新值，路径执行中改不动，限速表在提交路径时就算好了。`/set cmd_speed` 从下一条路径开始生效；加速度 `acc_linear` 下一拍就生效。

### 11.4 现场调速度的顺序

1. 先把 `AGV_SURVEY_SPEED_MM_S` 放低（100~150 mm/s），确认方向和位置都正常。
2. 逐步加 `AGV_SURVEY_SPEED_MM_S`，看 `DONE path` 行的 `max_cross` 和 `max_heading`。默认 `AGV_STOP_EACH_SEGMENT=1`（每个航点停稳再走），连续过弯只在驱动器堵转保护能关掉时再用。
3. 过弯冲出去触发 `AGV_ERR_POSE`（上位机显示“偏线过大或位置越界”）就降速度或降 `CHASSIS_ACC_LINEAR`；`AGV_CROSS_TRACK_MM` 现在默认 40 mm 是给 1200 mm/s 的实车过冲留的余量，不要再往上加。
4. 轮子打滑/丢步先查 `ZDT_RxDropped()` 和驱动器的堵转标志，再谈调参。

### 11.5 自动调参（调试台“自动调参”）

1. **测**：车放地上（轮子离地测不了：车身不转，陀螺仪看不到），周围空出 40 cm。调试台打开“自动调参”，点“开始测试”：车依次原地转 ±5°、±20°、±90°，勾上平移再前后左右各走 300 mm，回到原处，一分钟左右。每个动作的日志存在这台电脑的浏览器里，换电脑用导出、导入。
2. **训练**（测完自动开始，也可以勾选日志再点）：
   - 拟合车的模型：下发角速度 → 延迟 → 一阶惯性 → × K → 航向；平移时再加 `cx·vx + cy·vy` 的航向扰动。界面上有 K（小于 1 是打滑）、惯性、延迟、两个方向的扰动和拟合误差；点一段日志，模型按同样的命令算出来的曲线和实测叠在一起，对得上才说明模型可信。
   - 在模型上搜参数：按固件的航向环原样仿真（PI、积分区、限幅、到位死区、角加速度斜坡、0.1 RPM 量化、路径“进容差就算到”），跑转 90°/20°/5° 和前后、左右平移。分数是到位时间（进 `heading_tol` + 0.05° 以内、再没出去），加上超调（超过 0.3° 的每度算 1 s）和平移时的航向最大误差（每度算 2 s）。模型参数按各段日志之间的差别随机抽 11 辆车（蒙特卡洛），分数取平均和最差的中间，挑这批车上都好的 `heading_kp`、`heading_ki`；平移扰动积分顶不住时把 `heading_i_max` 一起加大。
3. **用、验证**：点“用到车上”发 `/set`，再点“再跑一遍验证”，用新参数跑同样的动作，逐个比预测和实测。对得上就把面板里的三个宏写回 `User/Chassis/chassis.h`；对不上就把新日志也勾上再训练一次（换了参数的日志让拟合更准）。

平时勾上“平时每个动作也存日志”（发 `/log on`），手动开、跑路线、比赛流程的每个动作都会存下来，也能拿来训练。日志格式见 `User/Comm/tune_log.h`：一个动作从第一拍记到结束后 0.4 s，最多 10 s；按发送缓冲的空余分批发，不挤掉状态行和回执，不占控制节拍。

限制：

- 只调航向环（`distance_kp` 现在用不到，见 11.1）。转得快慢的上限（`turn_max_speed`、`acc_angular`）不动，那是要不要打滑的取舍。
- 模型是线性的：打滑当成固定系数，平移扰动当成和车速成正比。换了地面、电池、载重要重新测。
- 只在主机测试里验证过（真实固件代码 + 有延迟、惯性、打滑的假车）：假车参数拟合得出来（K 0.900、惯性 40 ms、延迟 20 ms），推荐值放回假车上分数从 10.6 降到 6.0 s。**还没上过真车。**

## 12. 修复记录（2026-11，底盘单测前）

| 问题 | 现象 | 修复 |
|---|---|---|
| Cortex-M7 的 DWT 没解锁（`DWT->LAR`） | 不接调试器时 `CYCCNT` 不计数，`Chassis_Micros()` 恒为 0：定距/转向的超时保护永远不触发，而接着调试器时一切正常 | `Chassis_DwtInit` 写 `LAR = 0xC5ACCE55` |
| FDCAN Bus-Off 后不恢复 | 总线一次严重错误（插拔、短路、电机上电瞬间）后硬件停在 INIT，所有电机命令都发不出，只能断电 | `ZDT_Service()` 每拍检测 Bus-Off，Stop/Start 自动恢复并计数 |
| 堵转保护无法清除 | 驱动器 `Cgp_TF` 置位后一直保持，`S` 永远回不到 READY，只能断电 | 新增 `ZDT_ClearProtection()`（`0E 52 6B`）；`S` 清故障时自动解除保护、重新使能掉线电机，恢复后自动回 READY |
| 故障/未就绪没有原因 | 只能看到 IDLE/FAULT，不知道是哪个电机、哪个传感器 | `Chassis_WaitReason()` 位图 + `chassis.fault/fault_detail`，串口直接写出 `RF:no-reply`、`LR:stall` 等 |
| 电机安装方向写死 | 左右镜像安装的电机无法在软件里修正，只能去驱动器菜单改 | `CHASSIS_WHEEL_DIR_xx`（命令与反馈同时乘方向），配合 `W` 单轮测试 |
| 没有陀螺仪就不能动 | 反馈检查强制要求 IMU，底盘单测时永远停在 IDLE | `CHASSIS_USE_IMU=0` 时航向由四轮里程计推算 |
| 输出只有机器帧 | `$T/$V/$H/...` 20 Hz 刷屏，串口助手里不可读，依赖上位机 | 改为可读文本：事件行、回执、1 Hz 状态行（`D` 可调）、`H` 帮助、`I` 诊断 |
| 拐角限速压住整段直线 | 不管设多快，通往拐角的直线都只跑拐角速度（默认约 50 mm/s）：1000 mm 直线接 90° 弯要 21.9 s | 只在拐角内部的小段全程限速，直线靠刹车曲线减速；同一段路 5.5 s，直线跑满 300 mm/s，拐角 50 mm/s |
| 巡检第一个拐角就报 `AGV_ERR_POSE` | 偏线统计按位置找最近段，路线重复经过同一条边时会跳到后面重合的段（回库段和第一段重合），真正的下一段被排除，车一离开重合段就累计到 8 mm。原来的 `agv_test` 用假底盘，这条闭环没人跑过 | 偏线只量控制器正在走的段（`s_path_vertex`）；新增 `survey_loop_test` 用真实底盘跑完整圈：约 99 s，12 条通道全覆盖，最大偏线 2.5 mm |
| 帮助文字被截断 | `Printf` 缓冲只有 255 字节，超长的帮助被切掉 | 整段文字走 `ChassisTelemetry_Puts` |
| 紧贴黄色区域的障碍物认不出来 | 把黄色区域和粗加工区、暂存区当成高出地面的结构，附近 40 mm 的雷达点都丢掉；它们其实是平的，全场 1.5%~3% 的位置漏检 | 只过滤围挡和转盘；全场仿真全部认出 |
| 远处的障碍物认不出来 | 一簇要两个点，雷达又只看 1.8 m；对角 2.9 m 处 Ø50 每圈只打到一个点 | 看到 3.4 m，单点也算一簇，靠跨圈圈数滤误检 |
| 连上另一种固件后参数和模式是旧的 | 页面没清旧参数，还靠“有没有雷达参数”猜模式 | 连接和重启时清掉，用 `/mode` 问 |

## 9. 比赛模式：激光雷达与视觉串口

只在 `AGV_MODE=2` 时编译/启用（`main.c`、`freertos.c` 里的调用都包在 `#if AGV_MODE == AGV_MODE_COMPETITION` 中，`ser_port.c` / `competition.c` 在其他模式下编译为空），指令模式和跑图模式行为不变。参数集中在 `User/Config/comp_config.h`。

### 9.1 接线

| 外设 | 引脚 | 参数 | 对端 |
|---|---|---|---|
| USART1 | PA9 = TX → 雷达 RX，PA10 = RX ← 雷达 TX | 460800 8N1 | RPLIDAR C1（5V 单独供电，共地，3.3V 电平） |
| USART2 | PA2 = TX → 上位机 RX，PA3 = RX ← 上位机 TX | 115200 8N1 | 视觉上位机 |
| USART3 | PB10 = TX → 模块 RX，PB11 = RX ← 模块 TX | 9600 8N1（`COMP_SCANNER_BAUD`） | 二维码扫码模块 |
| TIM3_CH1 | PA6 → 舵机信号线 | 50 Hz，脉宽 500~2500 us 对应 0~180°（`COMP_SERVO_*`） | 伸缩雷达的舵机（单独稳压供电，共地） |

这三路串口和舵机都不进 `.ioc`：时钟、引脚、NVIC（优先级 6）都在 `SerPort_Init`、`Servo_Init` 里配置，串口是寄存器级中断收发 + 环形缓冲，不用 DMA（不涉及 D-Cache/MPU），CubeMX 重新生成不会覆盖。舵机脚不方便就换一个带定时器通道的脚，改 `User/Drivers/Servo/servo.c`。

### 9.2 雷达障碍物识别（`User/Navigation/lidar_obstacle.c`）

**安装。** 出发前外形不能超过 300 mm 见方（规则，出发后展开的不限），雷达装在舵机上，平时收在车身里。扫描时舵机把它从车身左后角伸出去，车身只挡住朝车身那 90°，其余 270° 都看得到。伸出去的位置默认按 C1（外径 55.6 mm）外沿贴着车角算：车体系 (-155, 155)。舵机角度和伸出去的位置都要装好以后量，现场先用 `/set servo_scan`、`servo_stow`、`lidar_x`、`lidar_y`、`lidar_yaw` 试，定稿写回 `comp_config.h`。

开局先在启停区停着扫一轮，之后伸着雷达边走边扫（9.6）。扫描的步骤：

1. 上电 600 ms 后发 STOP，20 ms 后发 SCAN（标准扫描，约 10 Hz、0.72°）；开始出点后关掉接收中断待命，要扫描时再打开，所以不用等雷达重新转起来。1 s 无数据自动重启，一轮超过 10 s 没扫完就放弃（`COMP scan failed`）。
2. 舵机转到 `servo_scan` 把雷达伸出去，等 `COMP_LIDAR_SERVO_MS`（800 ms）到位了才开始用点：伸到一半时雷达不在 `lidar_x`、`lidar_y`，换算出来的点全是错的。雷达没确定收好（伸着或正在转）时，它在车身左后角外面：规划和"能不能站"都把它当成车身外多出来的一个圆（`COMP_LIDAR_RADIUS_MM` 28 加余量 10 mm，`Map_SetAttachment`），这个圆也不能压障碍物、禁区、出场地。原地转之前先收回来：伸着转，扫过的圆从车角的 191 mm 变成 247 mm，板前会碰到板子。
3. 每个点按点到达那一拍的位姿和安装位置换算到场地坐标（走着时一拍 5 ms 只走 2 mm）。
4. 丢弃：落在车身轮廓（外扩 10 mm）里的点，朝车身那 90° 打到的是车身，离雷达 400 mm 也有；距离 < 50 mm（C1 最小量程）或 > 3400 mm（场地对角线）；离围挡 < 60 mm；转盘可能占到的那段上边。黄色区域、粗加工区、暂存区都是贴在地上的，雷达打不到，不过滤，否则紧贴它们的障碍物会漏掉。
5. 沿扫描顺序聚类（相邻点 ≤ 45 mm），簇弦长 ≤ 95 mm 视为 Ø50 圆柱；弧上点重心沿视线外推 2r/π 得圆心（视线从雷达算起）。一个点也算一簇：对角 2.9 m 处 Ø50 每圈只打到一个点左右，误检靠下一步的圈数要求滤掉。
6. 跨圈关联（60 mm）并平均。20 圈算一轮，一轮里至少 8 圈看到才算障碍物，`Map_AddObstacle(x, y, 45)` 写入栅格地图，接着扫下一轮。半径 45 = 25 + 定位误差：全场仿真（±30 mm 测距噪声）最坏约 24 mm。
7. 结束：换过三个位置（每轮结束时车所在的位置，相隔 300 mm 以上），又连续 30 圈没有新目标、没有待确认的，输出 `COMP scan end: stable observations`；记满 5 个位置（`place limit`）或开局 30 s（`time limit`）也结束。然后 `COMP scan done`、收雷达，之后不再处理雷达数据。

雷达扫描平面必须低于 100 mm（障碍物高度），伸出去的支架也不能挡在这个平面上，否则那个方向整片看不到。

**遮挡和视野。** 一个位置看不到正好被别的障碍物挡住的东西，车身又挡住朝车身那 90°，所以开局边走边扫，至少换三个位置，结果累加。开局摆车让左后角朝场地里面：启停区 1 车头朝 +Y（左后角朝左下），启停区 2 车头朝 +X（左后角朝左上，到板前才转到 +Y）。闭环测试（`comp_route_test`，真实的开局流程、识别和规划代码）两个启停区各 24 组随机摆放，88 个障碍物一个没漏，车身和伸着的雷达都没碰到东西。下表是原来停车扫三处时 1000 组随机摆放的仿真（雷达在 (-155, 155)），至少漏一个的布局占比，边走边扫的还没按这个规模重算：

| 障碍物数 | 启停区 1：扫一处 | 两处（加二维码板前） | 三处（再加场地中央） | 启停区 2：扫一处 | 两处 | 三处 |
|---|---|---|---|---|---|---|
| 3 | 4.0% | 0.1% | 0.1% | 3.7% | 0.0% | 0.0% |
| 5 | 11.1% | 0.1% | 0.1% | 13.1% | 0.3% | 0.1% |
| 8 | 30.2% | 1.6% | 0.5% | 29.7% | 1.9% | 0.2% |

和一圈都看得到的雷达差不多（扫三处 0.0%、0.0%、0.0%）。启停区 2 要是也车头朝 +Y 摆，左后角就在车的左下角、贴着下边的场地边伸不出去，三处扫完还漏 4.2%、7.3%、14.2%，去板子那段整段看不清。

**路上不撞还没看到的。** 每段路都是一条直线，只要看到的障碍物不挡这条线，被挡住的就不可能在这条线上：车身扫过的矩形是凸的，隐藏物在矩形里的话，它和雷达的连线也在矩形里，挡住它的东西就在这条连线上，会被看到（地图里障碍物外扩了 55 mm，比两个半径之和 50 mm 大）。这要求从这段路的起点扫过：第一段从启停区停着扫过的位置出发，严格成立；后面的路段是边走边看过的，走着时新看到挡路的障碍物会停下重新规划（`ROUTE stopped blocked`），但一轮约 2 s 才写一次地图，400 mm/s 时车会走出 800 mm，看到得太晚就来不及停。另一个前提是这个矩形在雷达的视野里：雷达在左后角，往左、往后走（偏 7° 以内）才成立；往车头或右边走，车身另一侧扫过的地方被车身挡着，这段路输出 `RUN move blind`（`RunLegSeen`）。启停区 1 去板子是后退，启停区 2 去板子是往左平移，去场地中央都是往左平移，都看得清；绕障碍物的路段会报 blind。沿板找码和读到码后沿板走回十字路口那一行不查。

### 9.3 视觉串口协议

### 9.5 任务码（`User/App/task_code.c`）

规则格式：四组三位数，以 `+` 连接。第 1、3 组是两批物料的颜色（按搬运顺序），第 2 组是第一批在粗加工区和暂存区的环号，第 4 组是第二批在粗加工区的环号。第二批在暂存区码垛到第一批同色物料上，环号不在码里，解析时推出来。

例：`156+123+516+231`

| 批次 | 搬运顺序 | 粗加工区环号 | 暂存区环号 |
|---|---|---|---|
| 1 | 红 黑 浅蓝 | 1 2 3 | 1 2 3 |
| 2 | 黑 红 浅蓝 | 2 3 1 | 2 1 3（码垛） |

颜色编号：1 红 2 黄 3 蓝 4 绿 5 黑 6 浅蓝，与 `VisionColor`、`vision/config.py` 一致。

- 合法条件：格式完整；每批三种不同颜色；第二批与第一批颜色相同；环号 1、2、3 各一次。不合法的内容打印原文后丢弃，已有的合法码不变。
- 第一个合法的码输出一次就定下来：扫码口的接收中断关掉，相机如果在找二维码也停掉，之后读到什么都不管。`/task <码>` 可以手动替换，`/task clear` 重新打开扫码口，都是台架用的。
- 单片机保存任务并决定下一步；取料时用 `Comp_SetVisionMode(VISION_MATERIAL, comp.task.color[批次][顺序])` 告诉上位机要找的颜色，上位机不保存任务码。相机通道（`VISION_QR`）只是备用，上位机把读到的原文用 TASK 帧发回来，走同一套解析。

扫码模块设置（固件不发配置命令，用模块手册里的设置码配好）：

1. 连续或感应读码模式：固件不发触发命令。
2. 关掉补光灯和瞄准灯：规则只允许垂直向下补光。
3. 串口 8N1，波特率与 `COMP_SCANNER_BAUD` 一致；有 CR/LF 后缀最好，没有也能靠 `COMP_SCANNER_IDLE_MS` 分行。

### 9.6 开局流程（`Comp_Start`，`User/App/competition.c`）

摆车：让左后角的雷达朝场地里面。读码时扫码模块要对着二维码板所在的那面墙（+X），按扫码模块在车的右侧算是车头朝 +Y（`COMP_QR_HEADING_DEG` = 90）。

| 启停区 | 车头朝 | 雷达那个角 | 扫码模块 | 板前 |
|---|---|---|---|---|
| 1（右上角，板子在下面） | +Y | 左下，朝场地里面 | 已经对着板子 | 不转 |
| 2（右下角，板子在上面） | +X | 左上，朝场地里面 | 朝下 | 收雷达原地转到 +Y 再读码 |

两个启停区摆法不一样，`COMP_START_HEADING_DEG(zone)` 分别是 90 和 0；扫码模块装在车头时要重新选。

上电：底盘使能 → READY 后 3 s 记下位姿（启停区中心、车头朝 `COMP_START_HEADING_DEG(zone)`；抽到另一个启停区时先用 `/pose` 改，调试台的“选启停区”按钮会把位置和朝向一起填好）→ 舵机把雷达收进来，雷达转起来待命。不会自己开动。

`/start`（比赛时要接启动按钮）后：

1. **启停区停着扫第一轮**（`RUN scan`）：舵机伸出 0.8 s，扫约 2 s，看到的障碍物写进地图、输出一次。第一段路要看清了才走。雷达不收，接着扫。
2. **边走边扫去二维码板前**（x 是 `COMP_QR_STOP_X_MM` = 2195，实装后按读码距离改；放在地图格子中间，停车差一两毫米还是同一格）。板子中心在 1100~1300 之间随机，找码从离来的方向近的那头开始：启停区 1 是 1300，启停区 2 是 1100；被障碍物占了，先在 1100~1300 里往另一头找，再往这段外面两头找，都不行就离板子远 50 mm 再找。启停区 2 到了还要原地转，找的是转得开的地方：车转到 45° 时的外接方框也放得下（雷达收着时车角扫过的半径 191 mm 的圆在里面）。A* 规划，伸着的雷达算进车身，只走第一段直线，到拐点按新地图重新规划。每轮扫描（约 2 s）结束把新看到的写进地图，挡了正在走的路就停下重新规划。扫码模块一直开着，读到第一个合法的码就输出并关掉。
3. **扫码模块没对着板子就原地转到 +Y**（启停区 2，`RUN turn`）：先停下扫描把雷达收回来，收好了再转，转完伸出去接着扫。**没读到就沿板慢慢找**（`COMP_QR_SWEEP_MM_S` = 50 mm/s）：往另一头走，到头还没读到就掉头，来回找；读到就停下。扫码模块没读到就让相机也找，开始找以后 10 s 还没有就报 `RUN failed task` 停下。
4. **扫描结束**（9.2 第 7 步，换过三个位置又没有新目标，最多 5 个位置、30 s）：输出 `COMP scan end`、`COMP scan done`，收雷达。之后不再处理雷达数据。
5. **读到码以后**：扫描已经结束就在板前收工（`RUN done`）；还没结束就先沿着板子走回十字路口那一行（y = 1205），再往左平移去场地中央换个视角，扫描结束或者到了场地中央就收工。中间的车道被挡住就不绕了。车停在原地。

雷达没接或坏了：第一轮等 10 s 超时，后面不再扫，直接走，读码后结束，一路都报 blind。去不了二维码板前（路全堵死，或者启停区 2 板前找不到转得开的地方）报 `RUN failed route`，车不动；转完朝向差超过 3° 报 `RUN failed turn`。

**后面按规则还要做、但还没有的：** 启动按钮、任务码和统计信息的显示装置；去转盘按顺序抓取第一批、放到车上、运到粗加工区按环号放置、再抓起来运到暂存区放置；回转盘做第二批，暂存区码垛；回启停区。这些要等机械臂。

## 13. 机械臂（`AGV_MODE=3`，`User/Arm/arm.c`）

### 13.1 结构和约定

- 并联 SCARA（平面五连杆），照 B 站“［25国特结构开源］并联式scara双工作区间搬运车”做的：两台 ZDT_X42S（X 固件）各带一根大臂，法兰轴直连，电机转多少大臂转多少；两根小臂在末端铰在一起，中间的关节都是被动的，没有别的电机和舵机。两台电机在车身中线上，连线和车头方向平行，和轮子在同一条 CAN 上（地址 5、6）。
- 车体系：x 朝车头、y 朝左，原点是底盘中心，mm。关节角 q1、q2 = 两根大臂相对车头的角度，俯视逆时针为正。
- 正解：两个肘各自绕电机转，两根小臂在两圆的交点交上。同一组关节角，末端可以在两个肘连线的任一侧（两种装配方式：从 J1 的肘看向 J2 的肘，左边 0、右边 1），电机读数分不出来，固件自己记着（`arm.side`，状态行的 `side=`）：上电是 `arm_mode`，只有过死点会换。逆解每根大臂两支，四种组合里挑合得拢、末端在现在这一侧、离死点够远的。
- 死点只算两根小臂成一条线：这时两台电机管不住末端。`Arm_Clearance` 算两根小臂的夹角离 0°/180° 多远；平常的运动目标要 ≥ `arm_margin`，走过去的一路上（关节空间每 1° 查一次）不能比两头和 `arm_margin` 里最小的那个还近。一边的大小臂拉直或折叠只是够得着的边，关节直着转过去肘换一边就行。
- 两个肘连线的两侧是两个工作区。图上的初始位置，两个肘在车左、末端在连线靠车里的一侧（side 1）：这一侧够得着车上，两根大臂一起顺时针摆过去还够得着车右外面和车头前面；车左的料盘、车左外面在另一侧（side 0）。实物上两根大臂不能互相交叉着绕过去，换侧只能过死点（13.2）。
- 默认尺寸按设计俯视图（`arm_calib.h`）：电机间距 200 是实物的，大臂 140 是图上标的，小臂 235 是按图的比例量的，图的右边当车头；图上那个姿态（两根大臂都垂直于中线）是 q = (90°, 90°)，末端在中线右边 73 mm，这就是初始位置。按这组尺寸：这一侧够得着车右外面 280 mm、车头前 250 mm；死点在末端到中线左边 37 mm 的地方，两根大臂张到 164.6°、15.4°，两个肘在 x = ±235，伸出车头车尾各约 100 mm；过去以后车左三个料盘（按图在中线左边 140 mm，x = 0、±100）都够得着，再回初始位置要过回来（主机测试固定了这几条）。小臂量准了在“几何和限位”里改，再标一次死点。

### 13.2 控制

- 规划：两个关节按距离比例分速度和加速度（`arm_speed`、`arm_acc`），同时出发同时到，关节空间走直线，也就是路径检查查过的那条线。发给电机的位置是规划位置最近 `arm_smooth` 毫秒的平均：梯形速度的加速度本来是一拍跳上去的，平均以后分几拍爬上去（40 ms 是 8 拍），起步和停下不冲；两个关节用同一个窗口，还在同一条直线上，发出去的位置追上了才报走完。过死点那一段不平均。离散时间的刹车公式保证不冲过目标，半路改目标速度连续。末端去 (x, y) 时，几组逆解里挑走过去不经过死点、离现在最近的（最近的那组不一定走得过去）。
- 下发：每 4 拍（20 ms）里第 0、2 拍发位置（走的时候 10 ms 一次，直通限速位置模式，绝对位置，限速比规划速度高 25%），第 1 拍读位置、第 3 拍读状态；停着每 100 ms 重发一次。一台驱动器一拍最多收两帧（见 `ZDT_Flush` 的分组），和底盘的读数排在同一拍也不超。
- 电机读数按零点折到 ±180° 再算关节角，电机多转了几圈也没关系；下发的位置 = 读数里关节角为 0 的那一圈 + 方向 × 关节角。所以每个关节的行程要在零点两边各 180° 以内（限位保证）。
- 状态：WAIT（等使能和位置）→ READY（锁住）；FREE（松开示教，先停再松）；FAULT（堵转、300 ms 没有位置、锁住时掉使能：两台都停；`S` 清保护、重新使能，3 s 内恢复）。急停发立即停止，等 30 ms 后的新读数对齐，锁在停下的地方。重新锁住、改零点、改方向也都先用实测位置对齐，臂不会跳。
- 跟随时按拍照那一刻的姿态换算：关节角历史存 0.64 s，用“收到时刻 − `arm_cam_lag`”插值。
- 过死点（`/arm swing`，或者去另一侧的点位时自动）：两个肘在两台电机连线的哪一侧，就走那一侧的死点。先按平常的规划走到助跑点，再让末端沿连线的中垂线走直线、从两个肘中间穿过去。两头都取末端离两个肘的连线 `arm_swing_run` 的地方：两头的关节角一样（电机张开到头再收回原来的角度），末端关于连线对称，小臂和连线的夹角一样大，甩过去、甩回来电机带末端的劲一样。按默认尺寸是中线右边 17 mm 到左边 183 mm，死点在 37 mm：里侧那一段 54 mm，外侧 146 mm。梯形速度：助跑那一段走一半加到 `arm_swing_speed`，匀速过死点，过了以后在后一半距离里收住，一共 1.5 × 200 / 400 = 0.75 s。（第一版两头按离死点各 60 mm 取：肘的连线自己在动，外侧那一头末端离连线只有 46 mm、小臂几乎还是一条线，实物上甩得过去、甩不回来。）关节角按逆解跟着：两台电机张开到头、速度降到零、再收回来，规划的两个肘的距离从不超过两根小臂的总长，所以不会互相顶；死点上那几毫米电机使不上劲，靠末端的惯性滑过去，慢了会停在死点上。死点前后规划的关节速度过零，这一段给驱动器的限速不低于 10 RPM，免得电机晚到、张不到头。走过死点那一拍固件换侧，打 `ARM side`。过死点时别的运动命令都 `BUSY`，`S` 照样急停。
- 电机支架要固定牢：死点上两台电机是沿它们的连线互相拉着的，支架能动，两个肘的距离就不是算出来的那个数，末端的劲也被支架吃掉。
- 电机读数分不出两侧：没甩过去时末端落回原来那边，固件却以为过去了，俯视图上末端画在另一边。这时 `/arm side`（调试台“末端其实在另一侧”）改回来，臂不动。
- 死点的位置要准：零点、小臂长度差一点，电机就会在死点多张或者少张一点。按估算两个肘的距离差 ±0.5 mm 以内、300 mm/s 时还过得去，越快容得越多。标法：松开电机，把两根小臂掰成一条直线，`/arm deadpoint` 按这时的关节角算出 `arm_b1/2`（两个肘的距离就是两根小臂的总长；掰得不太直影响很小，偏 5 mm 才差 0.1 mm）。电机读数只到 0.1°，算出来准到 0.03 mm 左右。
- 点位记着末端在哪一侧。`/arm go`、带侧的 `/arm j` 去另一侧的点：先查三段都走得通（去助跑点、过死点、从出口到那个点），再连着走完，走完才报一次 `ARM done`。`/arm xy` 只在现在这一侧找。

### 13.3 台架标定（调试台“机械臂”页）

1. 烧 `AGV_MODE=3` 的固件：`cmake --preset Release -DAGV_MODE=3`。两台电机在菜单里改 CAN 1M、地址 5（J1）、6（J2），和轮子并在同一对 CANH/CANL 上。
2. 连上调试台，“机械臂”页的状态从“等电机”变成“锁住”；等不到的话下面会写哪台没反馈、没使能。
3. 在“几何和限位”里填两台电机的位置、四根臂的长度（量轴心到轴心）。
4. 初始位置是两根大臂都垂直于中线朝车左、末端收在车上（q = 90°、90°，出发前就这样收在 300 mm 见方里）。上电前把臂摆成这样：驱动器的位置读数从上电那一刻的 0 开始算，零点默认 -90，上电以后固件就认这个姿态，不用标。摆得不准或者电机装反了，点“松开”，扶着摆好，点“设为零点”（只改参数，臂不动）。
5. 点“锁住”，先把 `arm_speed` 调到 30 左右，点一下 J1 +：俯视 J1 的大臂应该逆时针转，反了勾“J1 反向”；J2 一样。俯视图和实物对不上（末端画到了两个肘连线的另一边），点“换一种装配方式”（上电时末端在哪一侧）。
6. 标死点：点“松开”，用手把两根小臂掰成一条直线（末端夹在两个肘中间），点“标死点”，小臂长度按这时的关节角算出来。
7. 试过死点：电机支架先固定牢，把周围清空（那一刻两个肘伸到车头车尾外面各约 100 mm），锁住，点“过死点”。默认 400 mm/s、助跑 100 mm：停在死点上就把“过死点速度”或“过死点助跑”加大；没甩过去、末端落回原来那边而俯视图画到了另一边，点“末端其实在另一侧”。两个方向、空着和夹着物料都要试。
8. 记点位：用点动或者松开用手掰，把末端放到要记的地方，起名字点“记录当前位置”。点位记着末端在哪一侧，去另一侧的点会先过死点（列表里标“在另一侧”，俯视图上画成空心）。
9. 臂摆在初始位置，整车断电再上电，俯视图应该还是初始位置（读数从 0 开始、零点 -90）。只复位或重烧单片机、驱动器没断电时读数不丢，臂在哪都对；驱动器断过电，就要先摆回初始位置再上电。
10. 定稿后点“导出 arm_calib.h”，覆盖 `User/Config/arm_calib.h` 重新编译。比赛时不接调试台，用的就是这些参数和点位。

### 13.4 跟随物料

- 视觉上位机（`vision/`）接 USART2，协议同比赛模式（9.3 节）。机械臂模式一直发 MODE 帧（物料模式，跟随时带颜色，换颜色马上发），上位机按颜色过滤后回 MATERIALS 帧。
- 换算：相机装在小臂上（`arm_cam` = 1 或 2，跟着那根小臂转）时，偏差按拍照那一刻那根小臂的方向（减去 `arm_cam_rot`）转到车体系，原点是末端（`TARGET_PX` 标的是末端正下方）；固定在车上（0）时原点是 `arm_cam_x/y`，再转 `arm_cam_rot`。标方向：把那根小臂转到画面上方朝车头，点“当前小臂方向设为相机正向”（`/arm camdir`）。比例和左右在 `vision/config.py` 的 `MM_PER_PX`、`CAM_TO_BODY`。
- 跟哪个：要跟的颜色里离末端最近的那个；挪动不到 0.5 mm 不重新规划。够不着、或者走过去要过死点，就朝它走到能走的最远处，报 `far`；300 ms 没看到报 `looking`，停在最后看到的地方。
- 主机测试里相机装歪 30°、照片晚 60 ms：静止物料 2 s 内收敛到 0.3 mm 以内，18 mm/s 转着的物料误差 3.2 mm 以内。

### 13.5 还没验证的

- 没接过真电机和真相机。直通限速位置模式（`FB`）底盘没用过（底盘只用速度模式），第一次先把 `arm_speed` 调小。
- 电机上电后的位置读数是不是从 0 开始，看 13.3 第 9 步。
- 过死点在实物上试过第一版（2026-11-12，支架没固定）：从初始位置甩过去容易，甩不回来，原因是两头不对称，已经改成按离两个肘连线的距离取。改完以后只在主机测试里跑过：假电机没有惯性和摩擦，查的是规划出来的轨迹（两个肘从不超过小臂总长、过死点时末端是设定的速度、换侧的时刻）。实物上多快才稳、夹着物料行不行、零点差多少还能过，还要试。
- 提速（180 °/s、900 °/s²）和平滑（40 ms）也只在主机测试里跑过，实物上晃不晃要看。
- 固件不知道连杆之间会不会打架（只知道死点和关节限位）：实物上不能摆的姿态，比如两根大臂交叉，用关节限位或者中间点位避开。
- 小臂长度和料盘位置是按设计图比例估的（电机间距 200 是实物的）；小臂实长（或者标死点）、哪边是车头、料盘在哪，量了再看。
- 还没有夹爪和升降，现在只管平面上的两个关节。
